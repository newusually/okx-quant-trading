# OKX 量化交易系统 · 架构与全自动交易说明

**版本 build 0928G · 2026-09-28 · 部署目录 E:\finally-main**

---

## 一、一句话结论

**系统开机即全自动交易。** 搜索行情、判断信号、买卖下单、止盈加仓、查库存账——全部由 4 个纯 C++ 后台进程 + 1 个 Windows 守护服务完成，**不依赖网页、交易链路零 PHP、零人工介入**。浏览器面板只是一扇"玻璃窗"：能看，不能控制，拆掉窗户机器照转。

## 二、全链路架构总览

![全链路架构总览](images/arch_overview.png)

系统由 **6 个 C++ 组件**组成，全部编译为静态链接二进制（单个约 0.5~1MB），互相之间只通过 **MySQL 数据库**和**进程内 DLL 直调**通信，没有任何 PHP、Python 或脚本依赖。

### 2.1 组件清单

| 组件 | 运行方式 | 职责 | 关键点 |
|------|---------|------|--------|
| **tradehub.exe** | 常驻无窗口进程 | 交易引擎（核心） | 10 秒节拍：喂库→信号→闸门→下单→加仓→对账 |
| **tphub.exe** | 常驻无窗口进程 | 止盈中枢 | 10s 快检 +2% 止盈、跌时加仓、均价/ROI 全生命周期管理 |
| **datahub.exe** | 计划任务常驻 | 数据中枢 | 分级队列轮转拉取 477 合约 × 6 周期 K 线入库，全局匀速限流 |
| **apihub.exe** | 计划任务常驻 | 接口/面板服务 | :8090 提供 18 个只读接口 + C++ 直渲 K 线面板（纯旁观） |
| **guard.exe** | **Windows 服务** finally_guard | 守护进程 | 三级探活、崩溃 2 秒拉活、双开防护、计划任务自愈 |
| **sigcore.dll** | 进程内直调 | 信号算法库 | 金▲ 5m+3m 共振、KE 动能、ZigZag 转折点，常驻内存 K 线库 |

### 2.2 数据流向（对应上图编号）

1. **OKX → datahub**：REST 拉取 1m/3m/5m/15m/1h/4h K 线（自适应限速，429 自动退避）
2. **datahub → MySQL**：K 线入库（kline_* 表，列名 o/h/l/c/vol）
3. **MySQL ↔ tradehub**：C++ 直接读 K 线、直接写订单台账（trade_flow / position_detail）
4. **tradehub ↔ tphub**：持仓与止盈协同（10s 同拍）
5. **tradehub → OKX**：HMAC 签名市价下单/平仓（开仓、止盈、加仓全走这里）
6. **guard → 全部进程**：探活与自动拉活
7. **apihub ← MySQL / OKX**：只读查询 + fresh 直拉最新 K 线（仅服务网页展示）

**架构要点：交易主链路（1→5）是一条闭环，中间没有网页、没有 PHP、没有人工确认环节。**

## 三、全自动交易流程

![交易引擎10秒节拍](images/engine_tick.png)

### 3.1 交易节拍（每 10 秒一个循环）

| 时刻 | 步骤 | 说明 |
|------|------|------|
| T+0s | 止盈快检 | 扫描全部持仓，触及 +2% 止盈线立即市价平仓 |
| T+1s | 全池增量喂库 | 477 合约 × 5m/3m 新根喂入 sigcore.dll 内存 K 线库（去重 + 滚动 600 根） |
| T+2s | 买入信号扫描 | 5m 金▲命中后**再验 3m 金▲**，双周期共振才算有效信号 |
| T+3s | 六重风控闸门 | 见 3.3 节，任一不过直接放弃本信号 |
| T+4s | 市价开仓 | 每笔 1U · 20X 全仓交叉，HMAC 下单，trade_flow 台账落库 |
| T+5s | 跌时加仓检测 | 现价 < 均价且 3m 金▲ → 加仓 +1U/3 摊薄均价 |
| T+8s | 对账 + 快照 | 60s 周期与 OKX 账户对账，分钟级 pnl_history 盈利曲线落库 |

### 3.2 策略口径（当前生效：5m+3m 金▲共振）

- **买入**：5m 金▲ 与 3m 金▲ 同时命中（共振），回测 181 信号 / 胜率 57% / 均笔 +0.190%，优于旧 15m+5m 六维口径（381 信号 / 52% / +0.123%）
- **加仓**：仅跌时（现价 < 均价）3m 金▲触发，+1U/3 摊薄，不限轮数但有闸门
- **出场**：价格 +2% 止盈（ROI 40% 吃单），**永不止损**，只做多
- **金▲六维公式**（至少中一即触发）：① 自适应动能锚（KE 分位数阈值）② 缠论底分型 ③ CCI20<-100 后回升 ④ ADX14+MACD 柱抬升 ⑤ KDJ 超卖 ⑥ 反转阳线

### 3.3 六重风控闸门（代码级硬锁，AI 改不了）

| 闸门 | 规则 |
|------|------|
| 1. 持仓上限 | LockMaxPositions = 12 |
| 2. 每小时买入上限 | LockMaxBuysPerHour = 3 |
| 3. 单扫描新开仓 | LockMaxNewPerScan = 1 |
| 4. 冷却 | 同合约 60 分钟冷却；同一根 5m K 线只判 1 次 |
| 5. 大盘熔断 | ETH/BTC 15m × 4 根跌超 1% 禁止新开仓 |
| 6. 白名单 | 只买 symbollist.json 池内合约 |

加仓另有三闸门：单合约 30 分钟冷却 + 全局每小时 ≤6 次 + 同根 3m K 线只加 1 次（ARX 84 笔失控事故后加装）。

## 四、不打开网页能不能交易？

![网页依赖对照](images/no_web_dependency.png)

### 4.1 结论：可以，网页是纯旁观

| 链路 | 组成 | 是否必需 | 关掉后果 |
|------|------|---------|---------|
| **交易主链路** | guard + tradehub + tphub + datahub + MySQL | **必需** | 系统停止交易 |
| **旁观链路** | 浏览器 → Apache 反代 → apihub | **可选** | **零影响**，只是看不见了 |

### 4.2 实测证据（2026-09-28 静默观察 3 分 23 秒）

- 关闭所有浏览器进程，netstat 确认**无任何 ESTABLISHED 浏览器连接**
- K 线末根时间自驱推进（滞后仅 21 秒）
- pnl_history 盈利快照 709 行 → 712 行持续增长
- 心跳文件、trade_flow 流水全部正常刷新
- **证明：交易、盈利统计、加仓判断全部后台自驱完成**

### 4.3 PHP 的现状（诚实边界）

- **交易链路零 PHP**：下单、信号、对账、存库全部是 C++
- PHP 仅残留在**历史回测报告页**（Apache 服务的 *.php 展示页），属于"看报告"用途，与交易无关
- 浏览器 v2 面板零 JS、零下单能力，即使被恶意打开也发不出任何交易指令

## 五、数据存取：C++ 直接读写数据库

### 5.1 数据表地图

| 表 | 内容 | 写入方 | 读取方 |
|----|------|--------|--------|
| kline_instid_bar | K 线（o/h/l/c/vol） | datahub / apihub(fresh) / tradehub | tradehub · sigcore · apihub |
| trade_flow | 成交流水 | tradehub / tphub | apihub（展示） |
| position_detail | 持仓台账 | tradehub / tphub | tphub · apihub |
| pnl_history | 分钟级盈利快照 | tradehub | apihub（盈利曲线） |
| app_settings | 参数锁（闸门硬锁） | 人工 | tradehub（启动加载） |
| guard_status.json | 健康快照 | guard | 运维查看 |

### 5.2 存取方式

- 全部 SQL 由 C++ 内嵌 MySQL Connector 直接执行（预编译语句，全局互斥防并发冲突）
- sigcore.dll 内另建**常驻内存 K 线库**（滚动 600 根/合约），信号计算不打数据库，微秒级响应
- 数据库只崩不影响当根已喂入内存的信号判断；重启后自动从 DB 重新装载

## 六、守护与自愈（guard.exe · Windows 服务 finally_guard）

- **三级探活**：进程存在 → 心跳文件是否卡死 → HTTP/MySQL 是否真实可响应
- **崩溃拉活**：任何被守护进程退出后 **2 秒内自动重启**，加载最新二进制（换壳升级免手动）
- **双开防护**：hub 类进程自带 another_instance_running() 互斥，guard 侧再兜底 kill_duplicates
- **计划任务自愈**：定期 fixup 强制恢复开机自启/失败重启配置
- **看门狗**：单进程内存失控自动处置
- 当前守护 7 目标：datahub / apihub / tphub / phpfill / apache / mariadb / tradehub
